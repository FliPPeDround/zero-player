## 目标

游戏终止后不再只存 KV（10 分钟后被清理），而是把完整对局数据（每一步落子 + MCP 提供的 AI 理由 + 玩家/模型信息）持久化到 NuxtHub 数据库（SQLite），并作为公开 AI 数据集提供只读访问。

## 技术选型（已核实）

- 项目已装 `@nuxthub/core@0.10.8`，自带数据库运行时（含 `hub:db` / `@nuxthub/db` 虚拟模块，Drizzle ORM 封装）。本地无环境变量时用 libsql 驱动 → SQLite 文件 `.data/db/sqlite.db`；部署到 NuxtHub 时自动映射为 Cloudflare D1（同构 SQLite，schema 不变）。
- 需安装：`drizzle-orm`、`@libsql/client`（运行时）+ `drizzle-kit`（dev，用于生成迁移）。
- 配置：`nuxt.config.ts` 的 `hub: { kv: true, db: true }`（KV 保留不动）。
- 已通过 NuxtHub 官方文档确认用法：schema 放 `server/db/schema.ts`，`npx nuxt db generate` 生成迁移到 `server/db/migrations/sqlite/`，dev 启动自动应用；查询用 `import { db } from '@nuxthub/db'`（若该别名在 0.10.8 不可用则退回 `hub:db`，以 typecheck 为准）。

## 数据模型（`server/db/schema.ts`，新建）

- `games` 表：`id`（roomId，主键）、`gameId`（如 `gomoku`）、`status`（`finished`/`aborted`）、`name`、`createdAt`/`startedAt`/`finishedAt`（或 abortedAt）、`winner`（昵称）、`finishReason`（five-in-row / board-full / timeout / abandoned…）、`finishDetails`（JSON，如 winLine）、`players`（JSON：每方 nickname/model/harness/slot）、`moveCount`。
- `moves` 表：自增 `id`、`gameId`（外键→games.id）、`moveNumber`（1 起）、`nickname`、`side`（black/white）、`type`、`x`、`y`、`move`（人类记谱如 `H8`，复用 `gomokuMoveLabel`）、`reason`（AI 理由）、`at`（时间戳）。
- 隐私边界：不存原始 sessionId（公开数据集无意义且属内部标识）；每步时间戳从 `room.events` 的 move 事件按序 zip 到 `room.game.history`（每步恰好一个事件，若缺失则留空）。

## 采集接入点（`server/utils/room-store.ts`）

游戏只有两个终止转变，都接入 `persistFinishedGame(room)`（新建 `server/utils/game-dataset.ts`，try/catch 包裹、失败仅记日志，绝不影响对局流程）：

- `finishGame()`（胜负/和棋）— persistRoom 之后调用
- `abortRoom()`（超时/弃赛中止）— persistRoom 之后调用

该工具函数：跳过无 `room.game` 或 `history` 为空的对局；以 `onConflictDoNothing` 保证幂等；单事务插入 game + moves。KV 的 10 分钟保留窗口与定时删除逻辑**保持不变**——数据已落库，删除只影响实时房间。

## 公开只读 API（`server/api/dataset/`，新建，无需登录）

- `games.get.ts` — 对局列表（分页 + gameId/status 过滤）
- `games/[id].get.ts` — 单局详情（含全部落子步骤与理由）
- `export.jsonl.get.ts` — 全量 JSONL 导出（每行一个对局对象，机器学习常用格式）
